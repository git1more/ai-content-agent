## 各版修了什么、留了什么

### v1 · 首版

跑通链路，但八类缺陷并存：雨只在 S1/S2、S1 屏幕朝镜头、S1 颈长 0.36 头高、
S1 多出一根手指、S4 被读成流泪、S3 车牌乱码、S4 幼态化、手上抱头盔（构图风险）。

### v2 · 三层锁

**修好**：四镜全部有雨、手机背面朝镜头、颈长肩宽正常、S1 改单手消除两只右手。
**变糟**：加"不得流泪"后泪痕从一道变成两道粗泪柱；加"没有车牌"后车牌从乱码变成可读的
`TS 05 6`。→ 确立了"否定词反向强化"这条规律。

### v3 · 编译器

**修好**：结构性缺陷清零（单手、无同侧双手、无多指、无车牌）；S4 泪痕三版以来首次彻底消失；
S2 呼气白雾消失；S3 后视镜出现清晰人影（核心悬念成立）；发圈、右耳等细节补回。

**仍存在**：
- **头盔道具全片丢失**（v1/v2 有，v3 没有）——改单手构图时移除后未在后续镜补回，一致性评分因此每镜扣 0.05
- **S4 眼部仍偏大、幼态化未根治**——模型风格先验压过参考图约束
- **S1 手机面板全暗且无摄像头模组**，屏幕朝向存疑
- **S2 满月 + S4 单颗水珠**——关键帧干净，视频模型在运动中自行添加，提示词拦不住

## 两次作废运行（保留追溯）

### `_run1_identity_missing`

编译器只取表单里的 `subject`，未从形象卡注入身份特征。眼部三项 critical
（单眼皮 / 眼尾上挑 / 深褐瞳）全部丢失，S2 一致率从 0.925 掉到 0.777，
模型按默认审美把眼睛画圆画大。

**处置**：编译器改为强制注入身份特征，缺「眼」直接拒编。已进回归自检（事故⑦）。

### `_run2_narrative_missing`

表单迁移时丢失六处剧本要素（S1 发圈、S3 半盔、S3 后视镜人影、S4 右耳等）。
成片字幕写「后视镜里多了一个人」但镜中没有人影，声画不符；另 S2 天空出现暴雨夜
不该有的月牙。

**处置**：补回六项，`props.note` 接入编译器，剧本要素逐镜校验。

## 一条教训

v3 这一版跑了三次才拿到可用结果，两次作废都不是模型的问题，是**结构化迁移丢信息**：
第一次丢了身份特征，第二次丢了六处剧本要素。共同点是——先改写、后删除旧字段，
中间没有做完整性审计。

规则：**任何"散文提示词 → 结构化表单"的迁移，都必须先列信息点清单逐项核对，
确认全部落地后再删除旧字段。**
